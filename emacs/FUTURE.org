#+TITLE: Future Plugin Candidates
#+AUTHOR: Ryan Baltazar

Plugins and features to consider adding. Not currently needed, but worth revisiting.

* C# / Unity

| Plugin         | Purpose                                                | When to add                          |
|----------------+--------------------------------------------------------+--------------------------------------|
| =shader-mode=  | Syntax highlighting for =.shader=, =.cginc=, =.hlsl=  | If writing Unity shaders             |
| =glsl-mode=    | Syntax highlighting for compute shaders / raw GLSL     | If writing compute shaders           |
| =yasnippet=    | Snippet expansion (=[SerializeField]=, MonoBehaviour)  | If boilerplate becomes tedious       |

* C++

| Plugin          | Purpose                                      | When to add                           |
|-----------------+----------------------------------------------+---------------------------------------|
| =c-ts-mode=     | Tree-sitter C++ (built into Emacs 29+)       | When doing C++ work; pair with clangd |
| =cmake-mode=    | CMake file syntax highlighting               | If C++ projects use CMake             |
| =clang-format=  | Auto-format C++ on save via =clang-format=   | If team uses clang-format             |

* Navigator / Treemacs

** TODO Treemacs follows symlinks into separate projects

When the umbrella workspace contains symlinked directories (e.g. =docs/= → an external path), treemacs or =rb-toggle-navigator--ensure-treemacs-root= may add the symlink target as a separate project, or fail to prune it as a sub-project because the resolved path doesn't have the workspace root as a prefix.  Needs investigation into whether =treemacs-project->path= returns the symlink or the resolved target, and whether =file-truename= normalization is needed in the pruning logic.
